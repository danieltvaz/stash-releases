Build a plugin

A plugin is one JSON file. No code, no build step, no source access needed.

A "plugin" in Stash is what shows up as a type when you create a stash — an icon, a label, a one-line description, a set of default ignore patterns, and (optionally) a list of paths Stash offers to add automatically if they exist. The five built-in types (Code Project, Game Saves, Config/Dotfiles, Claude Config, Custom) are themselves ordinary plugin files — nothing about them is special-cased in the app.

Where it goes

Drop a .json file into Stash's plugin folder:

macOS~/Library/Application Support/stash/plugins
Windows%APPDATA%\stash\plugins
Linux~/.config/stash/plugins

The folder is created automatically the first time Stash runs, seeded with the five defaults. Restart Stash after adding or editing a file — plugins load once at startup, there's no live-reload.

The filename is the id

There's no id field to fill in. A file named unity-project.json becomes the type with id unity-project — that's also the value stored on any stash you create with it, so don't rename the file once you're using it (nothing breaks if you do; existing stashes just fall back to the Custom type).

Schema

label
string, required. Shown in the type picker and on the stash's detail panel.
icon
string, required. One of the names in the table below — anything else falls back to a generic box icon.
description
string, required. One line, shown under the label in the type picker.
defaultIgnores
string[], required (can be empty). Pre-fills the ignore list when this type is picked — see matching rules below.
suggestedPaths
string[], optional. Path templates Stash checks for and offers to add automatically — see placeholders below.

Ignore pattern matching

Each entry in defaultIgnores matches by bare file/folder name, at any depth inside the paths you back up — not the full path. A pattern starting with * matches by suffix; anything else has to match the name exactly.

node_modules matches a folder named exactly node_modules, anywhere inside what you're backing up. *.pyc matches any file ending in .pyc. There's no ** or mid-string wildcard support.

Suggested paths

Optional. Each entry is a template string — Stash checks whether it exists on disk and, if so, offers it as a starting point when you pick this type. Three placeholders are available:

{homeDir}
The current user's home directory.
{sep}
The platform path separator (/ or \) — use it instead of hardcoding either.
{rootFolder}
Defaults to .claude. Only meaningful if your plugin's id is claude-config, which gets a root-folder text field in the UI — every other plugin can ignore this placeholder.

Example

A plugin for Unity projects, saved as unity-project.json:

{
  "label": "Unity Project",
  "icon": "Gamepad2",
  "description": "Unity project folder. Skips build artifacts automatically.",
  "defaultIgnores": ["Library", "Temp", "Obj", "Build", "Logs", "*.csproj"],
  "suggestedPaths": []
}

Sharing a plugin

It's a text file — paste it in a gist, a message, a repo. Anyone who wants it copies it into their own plugin folder and restarts Stash. There's no registry or install command; that's deliberately out of scope for now.

Plugin files are pure data — no code ever runs from them. That's not a limitation we're planning to lift: it's why a plugin someone else wrote is safe to drop into your own Stash without a second thought.
